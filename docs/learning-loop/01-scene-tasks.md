# M1 · 任务式场景

## 需求与目标
进入场景前看清双方角色、三个沟通目标、可用提示；聊天过程中显示有原句依据的任务反馈。保留既有轮次与 XP，不能把轮数用作沟通能力证明。所有场景可直接进入。

## 功能设计与开发
- 独立 tasks.ts 提供咖啡馆/机场/酒店具体目标，其他已有场景提供通用沟通目标。
- SceneTaskBoard 用于准备页和会话内，已完成项可展开查看原句。
- 发送成功后主动评估当前用户原句，验证返回任务 ID 与原句引用。不存在的 ID、非原句证据不允许完成任务。
- 帮助与任务反馈使用独立状态，不影响原有对话、录音、轮次保存。
- 轮次完成与任务目标分别展示，未确认目标不显示“已掌握”。

## 测试
任务定义覆盖所有场景；空输入、未知任务、AI 幻觉证据过滤；多轮证据合并不丢失、不重复；接口失败保留已完成任务；切场景/退出时不回写旧结果。

## 验收标准
详情页可见三项目标；发送有意义的英语后出现真实 AI 辅助反馈；“Hello”不会仅因达到轮数就完成所有目标；原句可追溯；失败显示重试且继续可聊天。

## 实测结果
开发完成，本地 Web 验收通过。

- 实现：`src/lib/learning-loop/tasks.ts`、`scene-task-board.tsx`；接入 `scene-detail.tsx`、`scene-dialogue.tsx`。
- 独立测试：`pnpm test:learning:tasks`，3 项通过，覆盖全部 12 个已有场景。
- 真实 AI + 浏览器：Hello. 后 1/5 轮、0/3 目标；点中杯拿铁外带后 2/5 轮、3/3 目标，展开可见用户原句。
- 等待回复中重新开始，迟到的旧回复不改变新会话的 0/5 轮与 0/3 目标。
- 进度读取失败会禁用发送/开始并提供重试，避免覆盖旧数据；去掉“轮次解锁场景”的旧文案。
- 范围：任务原句证据属于本次会话，重新开始后重置；数据库仍保留原有最高轮次，不新增能力分或伪造掌握状态。
